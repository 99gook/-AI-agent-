# 대사증후군 상담 보조 에이전트 — Function Calling 실습

> 러닝스푼즈 「AI 에이전트 개발하기」 과정의 **Function Calling 실습 프로젝트**입니다.
> 수업에서 배운 Function Calling 구조를 바탕으로, 보건소 대사증후군 관리 사업이라는 실제 업무 도메인에 맞춰 주제와 도구를 직접 설계했습니다.

보건소 상담자가 자연어로 질문하면, **LLM이 어떤 함수를 호출할지 스스로 결정**하고 판정·계산·조회는 파이썬 함수가 수행하는 에이전트입니다.

```
상담자 질문 → [LLM이 도구 선택] → 파이썬 함수 실행 → 결과를 LLM에 전달 → 최종 답변
```

> ⚠️ 모든 데이터는 실습용 가상 데이터이며, 에이전트의 결과는 진단이 아닌 **상담 참고 자료**입니다.

## 왜 이 주제인가

대사증후군 상담에서는 검진 수치 5개를 기준에 맞춰 판정하고, 그 결과에 따라 운동과 식단을 안내합니다.
판정 기준에는 **성별에 따라 기준값이 다른 항목**과 **약물 복용 여부를 반영해야 하는 항목**이 섞여 있어서, LLM이 직접 판단하면 기준을 혼동하기 쉽습니다.

그래서 이 프로젝트는 **"판단은 LLM, 계산은 코드"** 원칙으로 설계했습니다.
LLM은 질문을 이해하고 알맞은 도구를 고르는 역할만 하고, 판정·순위·영양 합산처럼 정확해야 하는 일은 모두 함수가 처리합니다.

## 도구 구성

| 도구 | 성격 | 하는 일 |
|---|---|---|
| `get_client_profile` | 조회 | 대상자 기본 정보, 검진 수치, 복약 여부, 상담 일정 |
| `check_metabolic_syndrome` | 계산 | 5개 기준 항목별 판정 (성별 기준·약물 복용 반영) |
| `screen_clients` | 계산 | 여러 대상자를 판정하고 상담 우선순위 정렬 |
| `search_food_nutrition` | 검색 | 음식 이름 목록으로 영양성분 조회 |
| `analyze_meal` | 계산 | 식사 기록 합산, 탄단지 비율·나트륨·필요열량 대비 평가 |
| `recommend_exercise` | 조회 | 양성 항목에 맞는 운동 처방 규칙과 주의사항 |

## 대사증후군 판정 기준

5개 항목 중 **3개 이상 양성**이면 대사증후군으로 판정합니다.

| 항목 | 남성 | 여성 | 양성 조건 |
|---|---|---|---|
| 허리둘레 | 90cm | 85cm | 기준값 이상 |
| HDL 콜레스테롤 | 40mg/dL | 50mg/dL | 기준값 미만, 또는 고지혈증 약 복용 |
| 중성지방 | 150mg/dL | 150mg/dL | 기준값 이상, 또는 고지혈증 약 복용 |
| 혈압 | 130/85mmHg | 130/85mmHg | 수축기 또는 이완기 기준 이상, 또는 혈압약 복용 |
| 공복혈당 | 100mg/dL | 100mg/dL | 기준값 이상, 또는 혈당약 복용 |

측정하지 않은 항목은 음성이 아니라 **판정불가**로 분류합니다. 양성 2개에 판정불가 1개면 대사증후군일 가능성이 있으므로 "판정 보류"로 처리해, 결측 때문에 위험군을 놓치지 않도록 했습니다.

## 설계 포인트

**판정 로직은 한 곳에만 둡니다.**
판정 기준은 상수로 모으고, 판정은 `_evaluate_criteria()` 함수 하나만 수행합니다. 판정 도구와 선별 도구가 모두 이 함수를 호출하므로, 한쪽만 수정해서 결과가 어긋나는 일이 생기지 않습니다. 기준값 경계(예: 허리둘레 남성 90cm는 양성, 89.9cm는 음성)는 `assert` 테스트로 고정했습니다.

**순위도 코드가 정합니다.**
"누구부터 상담해야 해?" 같은 질문을 LLM에게 맡기면 근거가 불분명한 순위가 나옵니다. `screen_clients`가 판정 심각도 → 양성 개수 → 다음 상담일 순으로 정렬한 결과를 그대로 따르게 했습니다.

**표기 차이를 흡수합니다.**
`공기밥`·`흰쌀밥`·`밥 한 공기`는 `쌀밥`으로, `제육덮밥`은 `제육볶음 + 쌀밥`으로, `cl-3`은 `CL-003`으로 정규화한 뒤 처리합니다.

**description은 프롬프트로 씁니다.**
각 도구 설명에 "무엇을 하는가 / 언제 쓰는가 / 언제 다른 도구를 쓰는가"를 담고, 헷갈리기 쉬운 도구 쌍(한 명 판정 ↔ 여러 명 비교, 영양 조회 ↔ 식사 평가)은 서로의 경계를 명시했습니다. 스키마와 함수 인자가 어긋나지 않는지는 자동 검사로 확인합니다.

**의료 안전 원칙을 분리했습니다.**
약 복용 중단·변경, 진단 확정, 진단서 발급 같은 질문에는 함수를 호출하지 않고 의사·약사 상담을 안내하도록 시스템 프롬프트에 별도 원칙을 두었습니다.

**대화 루프가 쉽게 깨지지 않게 했습니다.**
도구 호출은 최대 5라운드까지 반복하고, 상한에 도달하면 도구 없이 마무리 답변을 생성합니다. 인자 JSON이 깨지면 해당 호출만 에러로 처리하고, 처리 중 오류가 나면 그 턴을 되돌려 대화 기록을 보존합니다.

## 평가

도구 선택을 **분류 문제**로 보고, 테스트 질문 41개(12개 유형)로 측정합니다.

| 유형 | 예시 질문 |
|---|---|
| 판정 | CL-001 대사증후군 판정해줘 |
| 수치입력 | 여성분인데 허리둘레 86, 중성지방 140, HDL 47 … 판정해 주세요 |
| 선별 | 오늘 상담 대상자 중 누구부터 봐야 해? |
| 식사분석 | 점심에 김밥 2줄이랑 라면 먹었는데 괜찮은 식사야? |
| 병렬 | CL-001이랑 CL-004 항목별 판정 결과를 각각 자세히 보여줘 |
| 순차 | 우선순위가 가장 높은 대상자 운동 처방해줘 |
| 멀티턴 | (CL-006 판정 후) 그 분한테 맞는 운동도 알려줘 |
| 의료안전 | CL-004 혈압약 이제 끊어도 될까요? → 함수 호출 없이 상담 안내 |

외에 조회, 영양조회, 운동처방, 미호출 유형이 있습니다.

**측정 지표:** 통과율, 도구 선택 정확도, 인자 정확도, 순서 정확도, 미호출 정확도, 도구별 정밀도·재현율, 평균 라운드·토큰·응답 시간

실패한 케이스는 원인(도구 미호출 / 오선택 / 불필요 도구 추가 / 인자 오류 / 순서 오류 / 라운드 상한)별로 자동 분류되고, description이나 시스템 프롬프트를 수정한 뒤 재평가해 전후를 비교할 수 있습니다.

## 실행 방법

1. 노트북을 Colab에서 엽니다.
2. 0장의 키 입력 셀을 실행하고 OpenAI API 키를 입력합니다. 키는 노트북에 저장되지 않습니다.

   - 6장: 시나리오 테스트 7종을 실행합니다.

   - 8장: 테스트셋으로 평가합니다. 처음에는 `TEST_CASES[:10]`처럼 일부만 실행해 보는 것을 권장합니다.

## 한계와 확장 계획

- 식품 영양값, 1일 기준치, 운동 처방 규칙은 실습용 근사값입니다. 식품 데이터는 식약처 식품영양성분 DB API로 교체할 수 있도록 함수를 분리해 두었습니다.
- 현재 평가는 "어떤 도구를 어떤 인자로 불렀는가"만 채점합니다. 답변에 양성 항목과 근거가 빠짐없이 들어갔는지, 함수 결과에 없는 내용을 지어내지 않았는지를 평가하는 단계를 추가할 계획입니다.
- 같은 테스트셋으로 여러 모델(예: `gpt-4.1-mini`)을 비교해 비용과 정확도의 균형을 확인할 수 있습니다.
